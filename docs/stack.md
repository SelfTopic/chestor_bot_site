следует, — [`spec.md`](spec.md), часть 0 и «Требования ко всему сайту».

## Часть 0 — языки проекта

✅ **0.1. Документация, комментарии в коде, тексты задач — на русском**, как в боте.

✅ **0.2. Коммиты — conventional commits на английском** (`feat(docs): ...`, `fix: ...`),

✅ **0.3. Тексты сайта** — в файлах переводов по языкам, не в разметке страниц: так

## Часть 1 — сайт: статическая сборка

✅ **1.1. Генератор — Next.js со статическим экспортом** (`output: "export"`, решено
06.11.2026). Тот же стек, что у chestor_site (`spec.md`, 0.8): компоненты и `tokens.css`
переносятся почти как есть, у владельца одни инструменты на два сайта, скрипты проверок
(скриншоты в двух темах, аудит доступности) — оттуда же. На выходе — статика для nginx,
Node на сервере не нужен. Цена — рантайм React на каждой странице (~60–80 КБ сжатого JS),
отсюда бюджет в `spec.md`, Н.1.

Отклонено: Astro (чистый HTML без JS, но компоненты chestor_site пришлось бы подключать
через `@astrojs/react` или переписывать — два стека), Hugo, свой генератор на Python.

✅ **1.2. Остальное:**
- Node.js 22+ и `pnpm`, как в chestor_site; только в CI и локально, на сервере Node нет.
- Стили — CSS Modules + CSS-переменные, без Tailwind и UI-китов (правило chestor_site).
  Свойства — логические (`margin-inline-start` вместо `margin-left`), чтобы RTL работал
  сам (`spec.md`, 0.7).
- Справка: Markdown → HTML через `remark`/`rehype` при сборке, шапка проверяется схемой —
  кривой файл роняет сборку (`spec.md`, 2.5).
- Поиск — Pagefind: индекс строится после сборки, на странице — небольшой скрипт и файлы
  индекса со своего домена (`spec.md`, 2.4, Н.2).
- Шрифты — Unbounded, Onest, JetBrains Mono, как в chestor_site; `next/font` скачивает их
  при сборке и раздаёт со своего домена (`spec.md`, Н.2). Для персидского и арабского —
  Vazirmatn: в этих трёх шрифтах арабского письма нет.

💡 **1.2.1.** Токены и общие компоненты двух сайтов — со временем вынести в общий пакет,
чтобы правка цвета не делалась дважды. Пока — копия с пометкой, откуда взята.

✅ **1.3. Справка — из репозитория бота при сборке.** CI сайта клонирует публичный
`SelfTopic/chestor_bot` и читает `docs/players/*.md` и `docs/players/en/*.md`. В
репозиторий сайта эти файлы не копируются.
- Папка справки — переменная `BOT_DOCS_DIR`; по умолчанию `web/.bot/docs/players`, её
  наполняет `pnpm fetch-docs` (частичный клон только `docs/players`, папка в `.gitignore`).
- Локально можно указать на свой клон бота: `BOT_DOCS_DIR=~/chestor_bot/docs/players`.
- Markdown → HTML: `unified` (`remark-gfm` — таблицы и сноски, `rehype-raw` — `<details>`).
  HTML из справки не чистится: источник — репозиторий владельца, правки в нём он ревьюит сам.

✅ **1.3.1. Раскладка репозитория:** `web/` — сайт (Next.js), `docs/` — документы; место
`api/` — под серверную часть (часть 3), когда до неё дойдёт.

🔲 **1.4. Когда пересобирать при изменении справки в боте.** Варианты:
- workflow бота при изменении `docs/players/` дёргает сборку сайта (`repository_dispatch`;
  в боте нужен секрет-токен с доступом к репозиторию сайта);
- сайт сам пересобирается по расписанию (раз в час или в сутки) и при пуше в сайт.

Рекомендация — первый вариант плюс ручной запуск сборки.

## Часть 2 — хостинг и деплой

✅ **2.1. Сервер — тот же, что у бота** (`spec.md`, 0.4). Там уже стоит nginx: он
проксирует вебхук бота (`chestor.site/webhook/bot`) и API квиза (`chestor.site/api`).
Сайт — ещё один `server_name chestor-bot.site` в этом же nginx, отдаёт папку со статикой.

✅ **2.2. HTTPS** — Let's Encrypt через certbot, как для `chestor.site`. `www` →
редирект на домен без `www`.

✅ **2.3. Деплой — готовая статика из CI.** GitHub Actions собирает сайт и кладёт его на
сервер по SSH (`rsync`) в папку сайта; сервер ничего не собирает. Ключ — отдельный
пользователь сервера, которому доступна только папка сайта. Выкладка — в новую папку и
переключение ссылки на неё, чтобы посетитель не застал наполовину залитый сайт.

✅ **2.4. Кеширование в nginx:** файлы с хешем в имени (`/_next/static/…` или `/_astro/…` —
по 1.1) — год, HTML — без долгого кеша; `gzip` (и `brotli`, если модуль есть).

🔲 **2.5. DNS.** A-запись `chestor-bot.site` (и `www`) на IP сервера — делает владелец у
регистратора.

## Часть 3 — серверная часть (для `spec.md`, части 3–4)

✅ **3.1. Сервис `api/`** (решено 07.11.2026) — Python 3.12, aiohttp, Poetry: стек владельца,
как у бота и сервиса `chat/` chestor_site. Браузер ходит только в него (`/api/*`), не в
сторонние API напрямую: ключи и сессии живут на сервере.
- Отдельный контейнер с лимитом памяти (`mem_limit`, порядка 64–128 МБ); падение или
  нагрузка сайта не трогают процесс бота.
- nginx отдаёт его на `chestor-bot.site/api/`; локально Next.js проксирует `/api/*` на него.
- Лимиты запросов на IP — в одном конфиге; ответ 429 с `Retry-After`.
- Проверки как в боте: ruff, pyright, pytest; в CI — отдельная задача.

✅ **3.2. Квиз** (`spec.md`, 1.4) — через `ghoul-quiz-lib`, как у бота и chestor_site.
- Своя сессия Ghoul Quiz: API не пускает одну сессию в двух местах. Вход — один раз
  `ghoul-quiz-register`, файл сессии — в volume, путь — `GHOUL_QUIZ_TOKEN_PATH`.
- Правильный ответ не уходит в браузер, пока на вопрос не ответили: сервер выдаёт вопрос
  с вариантами, проверяет ответ и только тогда показывает верный.
- Только вопросы без картинок: картинки API — ссылки на фандом, который не отдаёт их
  ботам. Вопрос «Кто это?» и любой с картинкой пропускается.

🔲 **3.3. ИИ-чат маскота** — отложен до этапа 2 (`spec.md`, 1.4.1).

🔲 **3.4. Живые данные** (`spec.md`, часть 3): в базу бота — отдельной ролью Postgres
только на чтение и только нужных таблиц; ответы кешируются на минуты.
