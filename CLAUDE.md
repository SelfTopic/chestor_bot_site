# chestor_bot_site

Сайт `chestor-bot.site` для Telegram-бота CheStor ([`SelfTopic/chestor_bot`](https://github.com/SelfTopic/chestor_bot),
локально — `~/chestor_bot`). Что строим — `docs/spec.md`, на чём — `docs/stack.md`,
метки решений ✅/🔲/💡 — `docs/README.md`.

## Сначала документы

- Новая часть сайта начинается с решения в `docs/`, а не с кода. Пункт 🔲 или с пометкой
  «предложение» — не делать, пока владелец его не подтвердил.
- Решение принято или изменилось — правь документ в том же коммите, что и код.

## Источник правды — бот

- Справка для игроков — `docs/players/*.md` бота. На сайте её не копировать и не
  переписывать: ошибку в справке правят в репозитории бота.
- Названия команд, цифры, шансы, формулы — сверять с кодом бота, а не с памятью или с
  `docs/design/` бота (там журналы решений, часть пересмотрена).
- Данные игры — только чтение. Сайт ничего не пишет в базу бота.

## Стиль

Как у `chestor.site/bot` (`~/chestor_site/web`, токены — `src/styles/tokens.css`), но для
игроков: без стека и архитектуры, тексты механик — из справки бота. Что берём и что
меняем — `docs/spec.md`, «Внешний вид».

## Ограничения

- **Сервер общий с ботом.** Всё, что можно посчитать при сборке, считается при сборке.
  Серверный процесс сайта — только с лимитом памяти и только с чтением базы.
- **Никаких внешних ресурсов на странице:** шрифты, скрипты, картинки — со своего домена.
  Без CDN, Google Fonts, счётчиков и трекеров.
- **Приватность как в боте:** о игроке — не больше, чем бот показывает в общем чате; раса и
  фракция могут быть скрыты (`docs/design/factions.md` бота, 0.6).
- **RTL с первого дня:** в CSS — логические свойства (`inline-start/end`), а не
  `left/right`; направление текста задаёт язык страницы.
- **Тексты — в файлах переводов**, не в разметке. Новая фраза — сразу на русском и
  английском.

## Комментарии

Как в боте: код читается сам, комментарий — только там, где из кода не видно «почему».
Одна-две строки, на русском. Не пересказывать код и не писать историю изменений.

## Проверки

Сайт — в `web/` (Next.js, статический экспорт в `web/out/`). Справка бота нужна для сборки:

```bash
cd web
pnpm install
pnpm fetch-docs          # или BOT_DOCS_DIR=~/chestor_bot/docs/players
pnpm lint && pnpm typecheck && pnpm test && pnpm build
```

Посмотреть собранное: `python3 -m http.server -d out 3000`. Готово — только после скриншотов
1440 и 390 px в обеих темах (`docs/stack.md`, 4.2.1).

Бэкенд — `api/` (Python, aiohttp, Poetry). В оболочке владельца `VIRTUAL_ENV` указывает на
глобальный Python pyenv, и Poetry принимает его за активное окружение — команды запускать
через `env -u VIRTUAL_ENV`, тогда окружение проекта — `api/.venv`:

```bash
cd api
env -u VIRTUAL_ENV poetry install
env -u VIRTUAL_ENV poetry run ruff check . && env -u VIRTUAL_ENV poetry run ruff format --check .
env -u VIRTUAL_ENV poetry run pyright && env -u VIRTUAL_ENV poetry run pytest -q
env -u VIRTUAL_ENV poetry run python -m chestor_api   # :8090, `pnpm dev` проксирует /api/* сюда
```

Без `GHOUL_QUIZ_EMAIL` и сохранённой сессии квиз работает на запасной колоде
(`api/chestor_api/data/fallback_questions.json`). Сессию бота локально не использовать: Ghoul
Quiz пускает одну сессию только в одно место.

## Секреты

Ключи деплоя, адрес и пользователи сервера, пароли базы — только в секретах GitHub Actions
и на сервере, никогда в коммитах.

## Git

Коммить логичными шагами, каждый коммит проходит проверки (`docs/stack.md`, 4.2).
Сообщения — conventional commits на английском (`feat(docs): ...`, `fix: ...`).
